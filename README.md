# 银行反欺诈告警关系分析与案件调查平台

基于 React、Mantine、Redux Toolkit、RTK Query、React Router、React Flow、Vite 和 TypeScript 实现的中文前端项目。项目使用浏览器 `localStorage` 模拟服务端数据库，不依赖外部后端即可运行。

## 功能

- 告警中心：关键词、风险等级、状态和渠道组合筛选，批量关联案件或排除。
- 案件工作台：案件列表、风险状态和调查工作量概览。
- **统一可恢复快照**：告警关联、案件字段、关系图谱、证据台账、结论版本写入同一份案件快照，每次保存递增 `revision` 并附带版本摘要（新增/移除节点、关系、证据、告警以及证据强度差异计数），可在“快照与恢复”页签随时恢复到任一历史版本（恢复本身也生成新快照）。
- **多窗口并发保存**：保存携带基准版本号，服务端做三方合并——无冲突字段与对方窗口新增实体自动并入，同一字段的冲突逐项列出，由调查员选择“用我的覆盖/采用对方”后提交。
- 关系图谱：账户、设备、IP、商户关系布局，节点拖动先进入本地草稿，随统一快照保存，关系解释与弱关联区分。
- 联动时间轴：交易、告警和证据按时间排序，点击后高亮对应关系。
- 证据台账：来源、发生时间、提交人、附件标识、证据强度和版本记录；可在草稿中新增、移除证据或调整强度。
- **证据驱动的结论失效**：每份结论锚定创建时的证据指纹；证据新增、移除或强度变化后，草稿/待复核结论自动置为“已失效”，列出新增、移除和强度差异，禁止继续复核，需重算新版本；失效版本永久保留，重启后仍可查。
- **失败草稿与重试**：保存前先将草稿（含冲突项选择）写入本地 outbox；保存失败后草稿跨重启保留，下次打开案件自动重试，也可手动重试或丢弃；无冲突改动先合并，冲突确认后覆盖。
- 审计报告：操作人和时间不可变留痕，保存、恢复、失效均入审计，支持 JSON、CSV 导出及演示数据重置。

### 并发保存的处理规则

1. 打开案件时记录基准版本 `baseRevision`，所有编辑先落在本地编辑器。
2. 保存时若服务端版本已前进，以“基准 / 服务端 / 本地”做三方比对。
3. 仅一方修改的字段、仅一方新增的节点/关系/证据、双方各自新增的告警关联自动合并。
4. 双方修改同一字段（或一方删除而另一方修改同一实体）列为冲突，弹窗逐项确认后才覆盖提交。
5. 保存失败（可在保存对话框勾选“模拟保存失败”体验）：草稿保留在本地，下次打开自动重试。

## 技术栈

- React 19 + TypeScript
- Mantine 9
- Redux Toolkit + RTK Query
- React Router
- React Flow
- Vite

## 运行

```bash
npm install
npm run dev
```

访问 `http://localhost:18458`。

## 构建

```bash
npm run build
npm run preview
```

`npm run build` 会先执行严格 TypeScript 检查，再生成 Vite 生产构建。

## 数据说明

首次打开时会将演示案件写入 `localStorage`。后续新增证据、结论、关系节点和状态流转会持久化到同一浏览器存储；“审计与报告”页面可以重置全部演示数据。
